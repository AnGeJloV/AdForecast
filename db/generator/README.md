# db/generator

Генератор синтетических данных AdForecast, откалиброванный по открытым реальным
данным (источники, лицензии и снятая статистика — в `realdata/README.md`).

Экономика окупаемости зависит только от характеристик, доступных модели
прогнозирования, плюс небольшой скрытый шум (по умолчанию sigma = 0,15):

- канал — базовая экономика площадки (CPC, CTR, типичный ROAS по бенчмаркам);
- дневной бюджет — насыщение отдачи на больших бюджетах и штраф обучения на малых;
- длительность — выгорание аудитории после первой трети кампании;
- месяц старта — сезонность спроса (пик ноябрь-декабрь, провал сентябрь);
- день недели — внутринедельный ритм спроса.

## Генерация и загрузка данных

```bash
python generate.py
docker exec -i adforecast-db-1 psql -U adforecast -d adforecast -v ON_ERROR_STOP=1 -1 < seed_data.sql
```

Флаг `-1` применяет загрузку одной транзакцией. Перед повторной загрузкой очистите данные: `TRUNCATE daily_metrics, uploads, campaign_access, campaigns, ad_accounts, forecasts, forecast_params, forecast_results, export_history, ml_models RESTART IDENTITY CASCADE`.

Параметры по умолчанию: 800 завершенных, 12 активных и 8 планируемых кампаний, около 46 тысяч дневных показателей, 6 CSV-выгрузок в `exports`. Полный список параметров: `python generate.py --help`. После генерации скрипт печатает сводку окупаемости по платформам.

Пароль пользователя БД берется из `deploy/.env`, при нестандартном значении замените `adforecast` в команде на `POSTGRES_USER`.

## cutoff_records.csv

Обучающая выборка формата «отсечка»: для каждой завершенной кампании четыре записи
состояния (0 %, 30 %, 55 %, 80 % длительности) с итоговой окупаемостью как целевой
переменной. Отсечка 0 моделирует планируемую кампанию без истории. Файл — вход для
разработки и проверки ML-модели без поднятого backend, в репозиторий не попадает.
Рабочая выгрузка для обучения собирается backend из базы по тому же принципу.

## Выгрузки рекламных кабинетов

`exports/*.csv` и `exports/*.xlsx` — файлы формата загрузки (FR-3), колонки: `date`, `impressions`, `clicks`, `cost`, `revenue`.

`exports/wizard_*` — фикстуры мастера загрузки: русские/английские названия колонок, разные разделители (`;`/`,`), десятая запятая/точка, форматы дат `ДД.ММ.ГГГГ`/`ММ/ДД/ГГГГ`, кодировка CP1251, бессмысленные названия колонок (распознавание по содержимому), файл с ошибочными строками. Используются для проверки `POST /api/campaigns/{id}/uploads/analyze` и загрузки с ручным маппингом.

CSV создает `generate.py`. Для XLSX требуется `openpyxl`:

```bash
python csv_to_xlsx.py exports/sample_upload_1.csv exports/sample_upload_2.csv
```

## Датасет для обучения

`export_dataset.sh` выгружает из БД выборку обучающих записей (платформа, бюджет, длительность, месяц, коэффициент окупаемости) в `dataset.csv`:

```bash
bash export_dataset.sh
docker cp dataset.csv adforecast-ml-service-1:/tmp/dataset.csv
MSYS_NO_PATHCONV=1 docker exec adforecast-ml-service-1 python -m app.train_local /tmp/dataset.csv
```

## seed_data.sql

Файл результатов генерации, в репозиторий не попадает. Для воспроизведения запустите `generate.py` с тем же `--seed`.
